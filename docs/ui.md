# 界面

## 任务驾驶舱（左侧栏「进度播报」）

0.5.0 起，左侧栏一级入口（与「插件 / 任务看板 / SSH」同级）是一个**任务驾驶舱**，0.5.1 起单会话详情从浮层抽屉改为会话视图里的「进度」标签页：

- **会话列表**：按工作区分组（目录名 + 完整路径，组头可折叠，折叠状态记在 localStorage；有运行中会话的组排前面）
- **会话卡片**：标题、已运行时长、本轮提醒次数、下次提醒倒计时、疑似卡住标记
- **搜索与筛选**：按标题 / 会话 ID / 目录搜索；筛选「全部 / 运行中 / 已提醒 / 疑似卡住 / 已静音 / 已结束」
- **会话「进度」标签页**（在「对话」「轨迹」之后，点列表卡片跳转过去）：
  - 每次提醒的**时间、原因**（计时到期 / 疑似卡住 / 手动）与触发时已运行时长
  - **最近汇报正文**：提醒发出后 agent 回给用户的那条正文（只取正文块，不含 thinking），最近 N 条，N 由设置项「汇报正文条数」控制（默认 3，0 = 不展示）
  - **当前工具已耗时**：面板每秒走表，不需要等下一次快照
  - **子 agent 树**：名称/标题、运行时长、静默时长、当前工具、停滞标记
- **立即催一次**：给该会话排一次手动提醒，下一个 step 生效（不受间隔与轮次上限约束）
- **本会话静音**：只挡自动提醒，`/progress` 与「立即催一次」仍然有效；内存态，重启即清

## 数据通道

| 端点 | 说明 |
| --- | --- |
| `GET /api/progress-tick/status` | 全量快照（轮询兜底） |
| `GET /api/progress-tick/events` | SSE，`snapshot` 事件推送同一份快照；25s 心跳 |
| `POST /api/progress-tick/nudge` | `{ sessionId }` 手动催一次 |
| `POST /api/progress-tick/mute` | `{ sessionId, muted }` 会话静音 |

页面优先用 SSE 实时更新，首帧到达前与断线期间自动退回 5 秒轮询（状态页会显示「实时推送 / 轮询兜底」）。SSE 连接在客户端做**模块级单例**：多个视图共享一条连接与一套轮询兜底，最后一个视图卸载时释放。

## 防护

这四条路由绕过 DSH 的 `/api` 认证桥，因此自己做门禁——仅回环地址、`Host` 必须是 `localhost` 或 IP 字面量（防 DNS rebinding）、写操作要求同源 + `content-type: application/json` + `x-progress-tick: 1` 自定义头、8KB 体积上限、每 60 秒 20 次限流。

## 到点了但提醒还没来？

提醒只在 **step 边界**（模型下一步开始前）注入。如果某一步特别长——比如模型流式
响应卡了十几分钟——那么截止时间会落在这一步内部，插件没有可以投递的位置，只能等
这一步结束立刻补发。

界面因此区分三种“到点”状态：

| 卡片显示 | 含义 |
|---|---|
| `下次提醒 1:20` | 正常倒计时 |
| `等待投递 · 本步 14 分 56 秒` + `已到点 · 等本步结束` | 已过截止时间，当前 step 还没结束 |
| `流式中断 15 分` | 当前 step 内连续 60 秒没有任何流式分片，多半是 provider 卡住 |

快照字段：`stepInFlightMs`（当前 step 已耗时）、`chunkGapMs`（距最后一个分片）、
`deliveryPending`（到点但被 step 挡住）、`stalled`（分片间隔 ≥ 60s）。
